# 移动端远程控制

在手机或平板的浏览器里操作这台电脑上的学习中枢：看主题与对话、发消息（可以拍照贴图）、
审批工具调用、中止当前轮。**不是屏幕共享**——手机上发的消息真的由这台电脑上的 agent 执行，
读写文件、跑工具都发生在本机。

入口：侧栏「远程控制」。打开后扫码，或在手机上打开链接。

---

## 1. 同一 WiFi（最简单）

1. 电脑上：侧栏「远程控制」→ 打开「启用远程控制」（默认监听范围就是「局域网」）。
2. 手机连同一个 WiFi，用相机扫面板上的二维码。
3. 打开后手机上看到的是这个工作区的对话列表；选一条对话就能直接聊。

链接形如 `http://192.168.1.5:8787/?t=<访问令牌>`。令牌是这条通道唯一的口令，
所以链接不要发到群里、也不要贴在公开的地方。

> 手机连不上？先看这两件事：Windows 防火墙是否拦了这个端口（首次监听时系统会弹窗，
> 要点「允许」），以及两台设备是不是真的在同一个网段（有些路由器把访客 WiFi 隔离了）。

## 2. 在外面用（需要一台公网服务器）

家里的电脑在路由器后面，手机从外面连不进去。三种办法，按「省事程度」排：

| 办法 | 要做什么 | 适合 |
| --- | --- | --- |
| **中继**（推荐，内置支持） | 在自己服务器上跑 `server/relay.mjs`，面板里填「中继服务器」 | 有一台 VPS，想随时能用 |
| **反向代理 / 隧道** | 用 nginx、cloudflared、frp 把公网地址指到本机端口，面板里填「对外地址」 | 已经有现成的反代或隧道 |
| 端口映射 | 在路由器上把端口映射到这台电脑 | 有公网 IP 且知道自己在做什么 |

### 2.1 中继

中继是仓库里的 [`server/relay.mjs`](../server/relay.mjs)：几十行、零依赖、只做字节搬运。

```bash
# 服务器上（需要 Node 18+）
mkdir -p /opt/learning-hub-relay && cd /opt/learning-hub-relay
# 把 server/relay.mjs 传上来，然后：
node relay.mjs --token <面板上的「中继口令」> --port 8787
```

想常驻就交给 systemd（**只新增一个服务，不动机器上别的东西**）：

```ini
# /etc/systemd/system/learning-hub-relay.service
[Unit]
Description=Learning Hub remote relay
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
ExecStart=/usr/bin/node /opt/learning-hub-relay/relay.mjs --token <口令> --port 8787
Restart=always
RestartSec=3
NoNewPrivileges=true

[Install]
WantedBy=multi-user.target
```

```bash
systemctl daemon-reload && systemctl enable --now learning-hub-relay
```

然后在面板里把「中继服务器」填成 `服务器IP:8787`（口令要与 `--token` 一致），
保存即会重连。之后二维码里的地址就是 `http://服务器IP:8787/?t=...`，**在哪儿都能扫**。

隧道是**本应用主动连出去**的：家里的路由器不用开任何端口，服务器上也不需要能回连到你。
中继看不懂你的内容（配对之后它只是一根管子），访问令牌始终由这台电脑校验。

### 2.2 反向代理

已经有一台带 HTTPS 的服务器（nginx、Caddy）或隧道（cloudflared、frp）时：
把公网地址反代到本机的 `127.0.0.1:8787`，然后在面板的「对外地址」里填那个域名
（例如 `https://hub.example.com`）。二维码与「复制链接」就会用它。

nginx 片段（注意 SSE 要关缓冲，否则手机上会「发了消息不动」）：

```nginx
location / {
    proxy_pass http://127.0.0.1:8787;
    proxy_http_version 1.1;
    proxy_set_header Connection "";
    proxy_buffering off;          # 事件流要实时推送
    proxy_read_timeout 1h;
}
```

这种用法建议把「监听范围」改成「仅本机」：端口不对外，只给反代用。

## 3. 安全

- **默认关闭**：不打开就不监听任何端口。
- **每个 `/api/*` 都要令牌**（`?t=`、`Authorization: Bearer` 或 `X-Remote-Token`），
  比较是常量时间的；连续错 20 次会被限流一分钟。
- **令牌分两把**：访问令牌（进链接，会出现在 URL 与浏览器历史里）与中继口令
  （只用于向中继证明「这条隧道是我的」）。任意一把都能在面板里一键更换。
- **能力边界**：远程只能读主题/对话、发消息、审批工具、取消当前轮。
  改不了设置、开关不了技能与 MCP、删不了主题、写不了任意文件。
  附件读取被限制在工作区内（`../` 一律拒绝）。
- **工作区外的访问申请不能在手机上批准**：那是「放开一个目录」的决定，面板上会提示
  回电脑处理。
- **明文 HTTP**：局域网直连与中继默认都是 `http://`，链路中间的人能看到内容与令牌。
  在意的话就放到 HTTPS 反代后面（见 2.2），把「对外地址」填成 https 域名。

## 4. 手机上的界面

回复里的内容与电脑上一致：Markdown、表格、代码块、思考过程（可折叠）、工具卡片（点开看结果与
图片）、演示卡片（```html / ```svg，沙箱 iframe，脚本不执行）、思维导图（Mermaid）。

**Mermaid 图是电脑画的**：手机页面里没有装 mermaid（那是一个 3.5MB 的库，再塞一份既重复
又会跟桌面端版本漂移）。页面遇到图就把源码发给电脑，电脑用它那唯一一份渲染器画成 SVG
再送回来——所以手机上看到的图和电脑上那张是同一个渲染器、同一套配色。电脑关掉时图会退回
显示源码，并说明原因。

**手机上不做的**（刻意留白，不是没做完）：编辑笔记、工作台（卡片 / 计划 / 资料 / 测验）、
讲解模式的操作台、技能与 MCP 面板、设置。这些是「坐下来干活」的动作，挤进手机屏幕只会
让真正要用的那几件事（看、问、批）变难用。

- **竖屏**：对话为主，左上角 ☰ 打开「主题 / 对话」抽屉。
- **横屏 / iPad**：宽到 720px 以上时，主题与对话固定到左边一栏，一屏同时看列表和对话。
- 顶栏：当前对话标题、连接状态（绿点=事件流已连上）、明暗切换、新建对话。
- 输入区：回车换行（宽屏上回车即发送）、相机按钮贴图（自动压到长边 1568px）、
  生成中可以点方块中止。
- 需要确认的工具调用会以卡片形式出现在输入框上方：允许 / 拒绝 / 本轮总是允许。
- 支持「添加到主屏幕」：加到桌面后是全屏打开的，像一个独立的小应用。

## 5. 排查

| 现象 | 原因与办法 |
| --- | --- |
| 手机上打不开页面 | 防火墙拦了端口；或两台设备不在同一网段；或服务没在跑（面板上看状态） |
| 页面打开但提示「需要访问令牌」 | 链接里的令牌被截断了，或换过令牌——重新扫码 |
| 发了消息不动 | 反代没关缓冲（`proxy_buffering off`）；或事件流被中间设备掐了 |
| 中继地址填了但还是连不上 | 中继进程没跑（`systemctl status learning-hub-relay`）；或口令与 `--token` 不一致 |
| 面板上「上次出错」有内容 | 端口被占用（换一个）、或隧道连不上（看提示里的地址） |

服务端的日志：本应用的日志在启动它的终端里（`[remote]` 开头）；中继的日志用
`journalctl -u learning-hub-relay -f`。
