# 移动端远程控制

在手机或平板的浏览器里操作这台电脑上的学习中枢：看主题与对话、发消息（可以拍照贴图）、
审批工具调用、中止当前轮。**不是屏幕共享**——手机上发的消息真的由这台电脑上的 agent 执行，
读写文件、跑工具都发生在本机。

入口：侧栏「远程控制」。打开后扫码，或在手机上打开链接。

---

## 1. 同一 WiFi（最简单）

1. 电脑上：侧栏「远程控制」→ 打开「启用远程控制」（默认监听范围就是「局域网」）。
2. 手机连同一个 WiFi，用相机扫面板上的二维码。
3. 打开后手机上看到的是这个工作区的对话列表；选一条对话就能直接聊。

链接形如 `http://192.168.1.5:8787/?t=<访问令牌>`。令牌是这条通道唯一的口令，
所以链接不要发到群里、也不要贴在公开的地方。

> 手机连不上？先看这两件事：Windows 防火墙是否拦了这个端口（首次监听时系统会弹窗，
> 要点「允许」），以及两台设备是不是真的在同一个网段（有些路由器把访客 WiFi 隔离了）。

## 2. 在外面用（需要一台公网服务器）

家里的电脑在路由器后面，手机从外面连不进去。**推荐用中继**：电脑主动连出去建隧道，
家里不用开任何端口、服务器上也不用装反代。

### 2.1 一键安装（推荐：只给 IP、用户名、密码）

面板上「一键装到我的服务器」那一栏填三样东西——**服务器 IP、SSH 用户名、密码**——
点「安装并连接」。应用会 SSH 上去做完这些事：

1. 探测系统与权限（root 或带 sudo 的账号都行，非 root 也能装到自己的家目录）；
2. 找 Node 运行时：服务器上已有就用已有的；没有就先试包管理器；再不行下载一份官方
   Node 运行时解到自己的目录里（**不改动系统里正在跑的任何服务**）；
3. 把中继脚本写到 `/opt/learning-hub-relay/relay.mjs`；
4. 起一个名为 `learning-hub-relay` 的 systemd 服务（没有 systemd 就退化成后台进程 +
   开机自启），监听 **54713** 端口——**不做反向代理**，中继自己听端口就够了；
5. 验证端口真的在监听，然后把「中继服务器」填好、把隧道接上。

装完之后二维码里的地址就是 `http://<你的服务器>:54713/?t=...`，**在哪儿都能扫**。
整个过程在面板上有实时日志，出问题也看得见（比如云服务商的安全组没放行这个端口）。

**密码只在点安装那一次用，不落盘**：日常使用靠的是中继口令（存在配置里），
只有重新安装才需要再输一次密码。服务器公钥指纹会被记住（TOFU），
下次连接发现指纹变了会拒绝——换机器了就在面板上点「重新信任服务器」。

> 为什么默认端口是 54713：8787 是 RStudio Server 的默认端口，5000/8000/8080 满地都是。
> 这个号在 IANA 的私有范围里，没有注册服务占用。想换就在「端口」里改（两边会一起换）。

### 2.2 手动安装（不想把密码给应用）

把 `server/relay.mjs` 传到服务器上，然后：

中继是仓库里的 [`server/relay.mjs`](../server/relay.mjs)：几十行、零依赖、只做字节搬运。

```bash
# 服务器上（需要 Node 18+）
mkdir -p /opt/learning-hub-relay && cd /opt/learning-hub-relay
# 把 server/relay.mjs 传上来，然后：
node relay.mjs --token <面板上的「中继口令」> --port 54713
```

想常驻就交给 systemd（**只新增一个服务，不动机器上别的东西**）：

```ini
# /etc/systemd/system/learning-hub-relay.service
[Unit]
Description=Learning Hub remote relay
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
ExecStart=/usr/bin/node /opt/learning-hub-relay/relay.mjs --token <口令> --port 54713
Restart=always
RestartSec=3
NoNewPrivileges=true

[Install]
WantedBy=multi-user.target
```

```bash
systemctl daemon-reload && systemctl enable --now learning-hub-relay
```

然后在面板里把「中继服务器」填成 `服务器IP:54713`（口令要与 `--token` 一致），
保存即会重连。

隧道是**本应用主动连出去**的：家里的路由器不用开任何端口，服务器上也不需要能回连到你。
中继看不懂你的内容（配对之后它只是一根管子），访问令牌始终由这台电脑校验。

### 2.3 反向代理（可选，默认不需要）

**默认不反代**：中继自己监听端口，手机直连它就行。只有当你想要 HTTPS
（公网明文 HTTP 的令牌与内容会被链路中间的人看到）时，才需要这一节。

已经有一台带 HTTPS 的服务器（nginx、Caddy）或隧道（cloudflared、frp）时：
把公网地址反代到本机的 `127.0.0.1:54713`，然后在面板的「对外地址」里填那个域名
（例如 `https://hub.example.com`）。二维码与「复制链接」就会用它。

nginx 片段（注意 SSE 要关缓冲，否则手机上会「发了消息不动」）：

```nginx
location / {
    proxy_pass http://127.0.0.1:54713;
    proxy_http_version 1.1;
    proxy_set_header Connection "";
    proxy_buffering off;          # 事件流要实时推送
    proxy_read_timeout 1h;
}
```

这种用法建议把「监听范围」改成「仅本机」：端口不对外，只给反代用。

## 3. 安全

- **默认关闭**：不打开就不监听任何端口。
- **每个 `/api/*` 都要令牌**（`?t=`、`Authorization: Bearer` 或 `X-Remote-Token`），
  比较是常量时间的；连续错 20 次会被限流一分钟。
- **令牌分两把**：访问令牌（进链接，会出现在 URL 与浏览器历史里）与中继口令
  （只用于向中继证明「这条隧道是我的」）。任意一把都能在面板里一键更换。
- **能力边界写在 `remote/bridge.rs` 的一张表里**（`ALLOWED` / `DENIED`，每条都带
  给用户看的原因），而且有个单测盯着「命令表里的每个命令都必须被分类」——
  新加命令忘了想「远程能不能用」会直接红。界线是：
  - **能用**：读界面要显示的一切；发消息、审批、取消；复习打分；写笔记；建卡片 /
    任务 / 测验 / 讲解方案；整理对话（改名、置顶、归档、分叉、删除）；记忆增删改；
    开内置浏览器标签。
  - **不能用**：改应用配置与密钥（`config_patch` 只放行「换模型 / 换明暗」两个字段，
    **「完全访问」这类权限分级明确不放**）、建/改/删主题、导入资料与重建知识库、
    直接写或删文件、更新应用、技能与 MCP 的定义与开关、桌面外壳（资源管理器 /
    系统程序 / 原生子 WebView）、以及一切不可逆的批量删除。
  - 这条线的依据：**「让 agent 代劳 + 点一下允许」能做到的事，远程也放开**（否则
    远程只是个残废的只读页）；而「改应用 / 改工作区结构 / 删东西」是坐下来才该做的。
- **附件读取被限制在工作区内**（`../` 一律拒绝）。
- **工作区外的访问申请不能在手机上批准**：那是「放开一个目录」的决定，面板上会提示
  回电脑处理。
- **明文 HTTP**：局域网直连与中继默认都是 `http://`，链路中间的人能看到内容与令牌。
  在意的话就放到 HTTPS 反代后面（见 2.3），把「对外地址」填成 https 域名。
- **一键安装用的 SSH 密码不保存**（只在内存里活一次），服务器公钥指纹会记住（TOFU）。

## 4. 手机上的界面

**手机上打开的就是电脑上那个界面**：远程服务把编译进二进制的同一份前端产物
（`dist/`）直接送出去，再注入一个 `shim.js` 把 `window.__TAURI_INTERNALS__`
换成「HTTP + SSE」的版本。于是同一套组件、同一份 CSS、同一批命令——
手机上点「发送」走的就是电脑上那个 `agent_send`，看到的是同一份对话文件。

```text
GET  /                 桌面端前端产物 + shim（不需要令牌）
GET  /assets/*         产物里的 JS / CSS（文件名带内容哈希，可长期缓存）
POST /api/invoke       {cmd, args} → 查白名单 → 交给电脑上的前端执行
GET  /api/events       SSE：电脑上的事件原样扇过来
GET  /api/file         工作区内的文件（消息里的图片）
GET  /api/tab-bytes    内置浏览器某个标签的原始字节（PDF / 图片）
```

为什么这么绕（而不是维护一套「手机版页面 + 手机版接口」）：两套界面必然漂移，
今天少个按钮、明天少个字段，而且每个功能都要在两边各写一遍。现在只有**一处**
适配（shim），加新功能时手机自动跟上。

由此带来的两个差异：

- **少数能力手机上天生没有**：窗口控制（那三个按钮）、系统文件选择框、原生子
  WebView、拖放导入。它们要么收起来，要么换成浏览器自己的做法（剪贴板、选图、
  新标签页打开链接）。远端网页在手机上会退回「阅读模式」（正文是电脑上那个内置
  浏览器提取好的）——网站会拒绝被手机页面嵌进去，这不是 bug。
- **「设置」与「工坊」两页手机上不给进**（点入口会说明原因）：那两页整个都是
  「改配置 / 造技能」，远程一条都不放行，让人点进去看一页点不动的开关不如直接说清。

- **竖屏**：对话为主，标题栏左上角 ☰ 打开「主题 / 对话」抽屉，点里面的东西自动收起。
- **横屏 / iPad**：宽到 900px 以上时侧栏常显，一屏同时看列表和对话。
- 标题栏：当前主题、连接状态（绿点=事件流已连上）、☰。
- 输入区：与桌面端一模一样（模型 / 思考强度 / 权限 / 图片 / 资料）。
- 需要确认的工具调用会以卡片形式出现在对话流里：允许 / 拒绝 / 本轮总是允许。
- 支持「添加到主屏幕」：加到桌面后是全屏打开的，像一个独立的小应用。

手机息屏或切网之后 SSE 会自己重连，重连时页面会重拉一次当前状态
（`hub://reconnect`），免得界面停在一个再也不更新的半截上。

## 5. 排查

| 现象 | 原因与办法 |
| --- | --- |
| 手机上打不开页面 | 防火墙拦了端口；或两台设备不在同一网段；或服务没在跑（面板上看状态） |
| 页面打开但提示「需要访问令牌」 | 链接里的令牌被截断了，或换过令牌——重新扫码 |
| 发了消息不动 | 反代没关缓冲（`proxy_buffering off`）；或事件流被中间设备掐了 |
| 页面上报「电脑上 30 秒没执行完…」 | 电脑那边的前端没响应（窗口卡住 / 正在退出）。手机上的一切操作都由电脑执行，这是它的固有代价 |
| 远端网页显示的是「阅读模式」正文 | 网站拒绝被嵌进手机页面（`X-Frame-Options`），这是预期行为；正文来自电脑上那个内置浏览器 |
| 中继地址填了但还是连不上 | 中继进程没跑（`systemctl status learning-hub-relay`）；或口令与 `--token` 不一致；或云服务商安全组没放行 54713 |
| 一键安装报「服务器公钥和上次不一样」 | 换了机器 / 重装了系统——确认无误后点「重新信任服务器」 |
| 一键安装卡在下载 Node | 服务器出网慢或被墙；先在服务器上装好 node 再点一次即可 |
| 面板上「上次出错」有内容 | 端口被占用（换一个）、或隧道连不上（看提示里的地址） |

服务端的日志：本应用的日志在启动它的终端里（`[remote]` 开头）；中继的日志用
`journalctl -u learning-hub-relay -f`。

开发时改完前端要 `npm run build`：远程送出去的是**编译产物**（`dist/`），
`npm run app:dev` 里那个热更新的页面只服务于电脑上那个窗口。改 `shim.js` 则要
重新编译 Rust（它是 `include_str!` 编进二进制的）。端到端验证：`npm run test:remote`。
